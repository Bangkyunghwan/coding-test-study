# 프로그래머스 84512 - 모음사전

- 문제 유형: DFS, 완전탐색
- 문제 링크: [https://school.programmers.co.kr/learn/courses/30/lessons/84512](https://school.programmers.co.kr/learn/courses/30/lessons/84512)
- 시간복잡도: O(N × 5^N) (문자열 생성 및 비교 포함)
- 공간복잡도: O(N²) (재귀 호출 스택 및 경로상의 문자열)

※ N은 만들 수 있는 단어의 최대 길이(이 문제에서는 5)이며, 입력으로 주어지는 목표 단어의 길이가 아니다.

## 접근 방식 및 사고 흐름

최근 DFS 문제를 많이 풀어서인지 이번 문제도 자연스럽게 완전탐색을 떠올렸다.

- 문자를 하나씩 추가하면서 가능한 단어를 만들어야 하고, 사전 순서도 지켜야 하므로 DFS를 사용했다.
- A, E, I, O, U 순서로 문자를 하나씩 붙여 DFS를 호출하면 사전 순서대로 단어를 탐색할 수 있다.
- 새로운 단어를 만들고 DFS를 호출할 때마다 `count`를 증가시켰다. 모든 재귀 호출에서 탐색 횟수를 공유해야 하므로 `count`는 멤버 변수로 선언했다. 최초의 빈 문자열은 카운트하지 않는다.
- 목표 단어를 찾았을 때 현재 DFS만 종료하는 것이 아니라 전체 탐색을 멈춰야 한다는 점을 고민했다. 이를 위해 `isFinished`라는 boolean 멤버 변수를 두고, 목표를 찾은 이후에는 새로운 DFS를 호출하지 않도록 구현했다.

```java
if (curWord.equals(targetWord)) {
    isFinished = true;
    return;
}
```

## 시행착오

### 1. 메모리 초과 - 탐색 깊이를 제한하지 않음

처음에는 목표 단어와 일치할 때만 DFS를 종료하도록 구현했다. 하지만 메모리 초과가 발생했다.

처음에는 반복적으로 문자열을 생성하거나 `"AEIOU".toCharArray()`를 호출하는 것이 원인이라고 생각했다. 모음 배열을 멤버 변수로 옮겨 보려고 했지만 이것이 근본적인 원인은 아니었다.

실제 원인은 DFS의 탐색 범위를 제한하지 않은 것이었다. 목표 단어가 `E`라면 다음과 같이 A만 계속 추가하게 된다.

```text
"" → A → AA → AAA → AAAA → AAAAA → AAAAAA → ...
```

재귀 호출이 종료되지 않아 다음 문자를 탐색할 수 없고, 호출 스택과 문자열 객체가 계속 쌓인다.

기존에 풀었던 DFS 문제들은 주어진 배열의 인덱스를 따라가거나 행 번호를 전달했기 때문에 자연스럽게 탐색 범위를 제한하고 있었다. 너무 당연하게 처리하던 부분이라 이번에는 별도의 종료 조건이 필요하다는 점을 의식하지 못했다.

따라서 단어의 최대 길이인 5를 기준으로 종료 조건을 추가했다. 목표 단어와의 일치 여부를 먼저 검사해야 길이 5인 단어도 찾을 수 있다.

```java
if (depth == 5)
    return;
```

### 2. 메모리 초과 - 재귀 호출 인자에 ++depth 사용

깊이 제한을 추가했는데도 메모리 초과가 발생했다.

```java
dfs(curWord + c, ++depth); // 잘못된 코드
```

`++depth`는 다음 재귀 호출에 전달하는 값뿐만 아니라 현재 호출의 지역 변수 `depth` 자체도 변경한다.

현재 깊이가 4라면 첫 번째 자식에게는 5가 전달되지만, 두 번째 자식에게는 6, 세 번째 자식에게는 7이 전달된다. 같은 부모에서 탐색하는 자식들의 깊이가 달라지고, `depth == 5`라는 종료 조건을 건너뛰게 된다.

```java
dfs(curWord + c, depth + 1); // 수정
```

현재 호출의 상태는 유지하고 다음 호출에 전달할 값만 계산해야 한다. 단, `count++`처럼 의도적으로 공유 상태를 변경하는 경우에는 증가 연산자를 사용해도 된다.

## 배운 문법 및 구현 방법

- `String`은 직접 for-each문으로 순회할 수 없다. `"AEIOU".toCharArray()`로 `char[]`를 만들어 순회하거나 `charAt()`을 사용한다.
- `curWord + c`처럼 String 뒤에 char를 붙일 수 있다. String은 불변 객체이므로 기존 문자열은 변경되지 않는다.
- 문자열 리터럴 `"AEIOU"` 자체는 반복 호출마다 새 객체를 만드는 것이 아니지만, `toCharArray()`는 호출할 때마다 새 배열을 생성한다. 이번 문제의 정상적인 탐색 범위에서는 메모리 초과의 원인이 아니다.
- `++depth`는 증가시킨 값을 전달하고, `depth++`는 기존 값을 전달한 뒤 증가시킨다. `depth + 1`은 기존 변수의 값을 변경하지 않는다.

## AI에게 물어본 모범 답안 (참고용)

```java
class Solution {
    private int count = 0;

    public int solution(String word) {
        count = 0;
        dfs("", word);
        return count;
    }

    private boolean dfs(String curWord, String target) {
        if (curWord.equals(target))
            return true;

        if (curWord.length() == 5)
            return false;

        for (char c : "AEIOU".toCharArray()) {
            count++;

            if (dfs(curWord + c, target))
                return true;
        }

        return false;
    }
}
```

탐색 방식 자체는 내 풀이와 같다. 구현상의 차이는 다음과 같다.

- 별도의 `depth` 변수 없이 `curWord.length()`로 현재 깊이를 판단할 수 있다. 이미 가지고 있는 값에서 필요한 정보를 얻을 수 있다면 굳이 상태를 추가할 필요가 없다.
- `isFinished` 대신 DFS의 boolean 반환값을 사용한다. 하위 호출에서 목표 단어를 찾으면 `true`를 반환하고, 상위 호출도 이를 확인해 `true`를 반환하면서 전체 탐색을 종료한다.

아직 DFS의 반환값을 문제 상황에 맞게 활용하는 것이 어렵기 때문에, 이번에는 기존의 멤버 변수 방식으로 해결한 것에 만족하고 반환값을 활용하는 방식은 추후에 다시 고려하기로 했다.


## 추후 DFS 문제에서 기억할 점

1. 무엇을 탐색하고 어떤 순서로 탐색할 것인지 결정한다.
2. 각 DFS 호출이 어떤 상태를 가지고 있어야 하는지 생각한다.
3. 탐색 범위와 종료 조건을 반드시 확인한다. 깊이 변수 자체가 필수인 것은 아니지만 재귀가 어디서 끝나는지는 명확해야 한다.
4. 다음 재귀 호출에 값을 전달할 때 현재 호출에서 유지해야 할 변수까지 변경하지 않는지 확인한다.
5. 현재 호출만 종료할 것인지, 전체 탐색을 종료할 것인지 구분한다.

**핵심:** DFS에서 메모리 초과가 발생하면 무작정 객체 생성량부터 의심하지 말고, 재귀 호출이 정상적으로 종료되는지 먼저 확인하자. 특히 각 호출에서 유지되어야 하는 상태와 다음 호출에 전달할 값을 구분하자.
