# 프로그래머스 42862 — 체육복

## 1. 문제 정보

- **문제:** [프로그래머스 42862. 체육복](https://school.programmers.co.kr/learn/courses/30/lessons/42862)
- **난이도:** Level 1
- **유형:** 그리디(Greedy), 구현, 배열을 이용한 상태 관리
- **핵심:** 체육복을 도난당한 학생에게 앞뒤 번호 학생이 여벌 체육복을 빌려주어, 수업에 참여할 수 있는 학생 수를 최대로 만든다.

학생 번호는 `1`부터 `n`까지이고, 학생은 **바로 앞번호 또는 뒷번호 학생**에게만 체육복을 빌릴 수 있다.

### 반드시 확인해야 할 조건

> 여벌 체육복을 가져왔더라도 한 벌을 도난당한 학생은 남은 체육복 한 벌을 자신이 입어야 하므로 다른 학생에게 빌려줄 수 없다.

따라서 `lost`와 `reserve`에 **동시에 존재하는 학생**은 빌릴 필요도 없고, 빌려줄 수도 없다.

또한 문제에서 `lost`, `reserve` 배열이 정렬되어 들어온다고 보장하지 않는다.

---

## 2. 처음 생각한 접근 방식

처음에는 `lost` 배열을 순회하면서 해당 학생에게 체육복을 빌려줄 수 있는 사람이 있는지 검사했다.

1. 체육복을 도난당한 학생 `l`을 순회한다.
2. `reserve`에서 `l - 1`, `l`, `l + 1` 번호를 순서대로 확인한다.
3. 빌릴 수 있으면 `reserve`의 해당 값을 `999`로 변경하여 다시 빌려주지 못하도록 한다.
4. 아무에게도 빌리지 못한 학생만 전체 학생 수에서 제외한다.

앞사람에게 우선적으로 빌리게 한 이유는 **뒷사람의 여벌 체육복을 그 다음 학생에게 남겨두는 편이 유리할 수 있다고 판단했기 때문**이다.

중복된 코드를 줄이려고 `check()` 메서드로 분리하기도 했지만, 처음 코드와 동작 원리는 같았으므로 같은 이유로 오답이 나왔다.

### 오답의 원인 ①: 문제 조건을 다르게 해석함

처음에는 `lost`와 `reserve`에 동시에 포함된 학생도 다른 학생에게 체육복을 빌려주거나, 자신이 다른 학생에게 빌려 입는 식으로 체육복을 재배치할 수 있다고 생각했다.

예를 들어:

```text
n = 5
lost = [2, 3]
reserve = [1, 2]
```

처음 생각: 2번이 1번에게 빌리고, 자신에게 남아 있던 한 벌을 3번에게 빌려주면 전원이 참여할 수 있지 않을까?

하지만 문제에서 **여벌을 가져왔다가 도난당한 학생은 다른 사람에게 빌려줄 수 없다고 명시**한다. 즉, 2번 학생은 자기 체육복 한 벌만 사용할 수 있다. 1번 학생의 여벌 체육복도 3번까지 전달할 수 없으므로 이 예시의 정답은 **4명**이다.

**배운 점:** 전체 체육복 개수가 충분한지뿐 아니라, **누가 누구에게 빌려줄 수 있는지에 관한 제한**을 정확히 반영해야 한다.

### 오답의 원인 ②: `lost`를 정렬해야 함

앞번호부터 처리하고 앞사람에게 먼저 빌리는 전략이므로, `lost`를 오름차순으로 순회해야 한다.

```text
lost = [3, 1]
reserve = [2, 4]
```

- 입력 순서대로 처리: 3번이 2번에게 빌리면 1번은 못 빌림 → 참여 인원이 줄어듦.
- 오름차순으로 처리: 1번이 2번에게, 3번이 4번에게 빌림 → 모두 해결.

따라서 `Arrays.sort(lost);`가 필요하다. `reserve`는 전체를 검색하는 내 방식에서는 정렬할 필요가 없다.

## 3. 최종적으로 해결한 내 풀이: ArrayList 사용

### 생각의 흐름

1. `lost`를 정렬한다.
2. `int[]` 배열을 `ArrayList<Integer>`로 변환한다.
3. `lostList`와 `reserveList`에 **동시에 있는 번호**를 양쪽에서 삭제한다.
   - 해당 학생은 자기 체육복을 입지만, 다른 사람에게는 빌려줄 수 없다.
4. 남은 `lostList`를 앞번호부터 순회한다.
5. 앞사람에게 먼저 빌리고, 실패하면 뒷사람에게 빌린다.
6. 이미 빌려준 학생은 `999`로 표시해 중복 대여를 막는다.
7. 둘 다 실패한 경우에만 참여 인원을 하나 줄인다.



### 주의했던 부분

- `lostList.remove(i)`는 인덱스 `i` 의 원소를 삭제한다.
- `reserveList.remove(Integer.valueOf(num))`는 **값이 `num`인 원소**를 삭제한다.
- 리스트에서 삭제하면 뒤쪽 원소들이 한 칸씩 앞으로 당겨지므로, 인덱스를 이용한 반복문에서는 `i--`로 다음 원소를 건너뛰지 않게 했다.
- `check()`가 대여 성공 여부를 반환하게 해서 `continue`로 다음 학생의 검사로 넘어갔다.
- `999`로 사용된 여벌을 표시하는 방식은 유효하다. 다만 `ArrayList`를 사용하므로 값을 **삭제**해도 된다.

예를 들어 `check()`는 다음처럼 줄일 수도 있다.

```java
private boolean check(int num, ArrayList<Integer> reserveList) {
    return reserveList.remove(Integer.valueOf(num));
}
```

`remove(Object)`는 해당 값을 제거했으면 `true`, 없으면 `false`를 반환한다.

### 시간·공간 복잡도

- 시간 복잡도: **O(N²)** (리스트의 `contains`, `remove`, `check`에서 선형 탐색/이동 발생, 정렬 비용은 이에 비해 작음)
- 추가 공간 복잡도: **O(N)** (두 리스트 저장)
- 이 문제는 학생 수가 최대 30명이어서 충분히 통과할 수 있다.

## 4. 왜 이 풀이가 그리디인가?

그리디는 **모든 선택지를 끝까지 탐색하지 않고, 현재 상황에서 유리한 선택을 확정하며 답을 구하는 방식**이다.

내 코드에서 그리디 전략은 다음 두 가지다.

1. 체육복을 잃어버린 학생을 **번호가 작은 순서부터** 처리한다.
2. 앞뒤 모두에게 빌릴 수 있으면 **앞사람에게 먼저** 빌린다.

예를 들어:

```text
lost = [2, 4]
reserve = [1, 3]
```

- 2번이 3번에게 빌리면 4번은 체육복을 빌릴 수 없다.
- 2번이 1번에게 빌리면 4번도 3번에게 빌릴 수 있다.

앞번호부터 처리한다는 전제하에, 현재 학생의 **앞사람은 이후 학생에게 빌려줄 기회가 없다**. 반면 **뒷사람은 바로 다음 학생에게 빌려줄 가능성이 있다**. 그래서 앞사람에게 우선적으로 빌리는 선택이 이후 학생의 기회를 해치지 않는다.

중요한 점은 **그리디 = 반복문**이 아니라는 것. 특정 기준에 따라 선택을 확정하고 되돌아가지 않는 **전략**이 그리디다. 모든 문제에서 현재 좋아 보이는 선택이 정답인 것은 아니므로, **왜 그 선택이 최적해를 보장하는지** 확인해야 한다.

## 5. 다른 풀이: 학생 번호를 배열 인덱스로 사용하기

나중에 더 간단한 풀이도 알게 되었다. 별도의 `lostList`, `reserveList`를 만들지 않고 **각 학생이 가진 체육복의 개수**를 하나의 배열로 관리하는 방식이다.

```java
import java.util.*;

class Solution {
    public int solution(int n, int[] lost, int[] reserve) {
        int[] clothes = new int[n + 2];
        Arrays.fill(clothes, 1);

        for (int l : lost) {
            clothes[l]--;
        }

        for (int r : reserve) {
            clothes[r]++;
        }

        for (int i = 1; i <= n; i++) {
            if (clothes[i] != 0)
                continue;

            if (clothes[i - 1] == 2) {
                clothes[i - 1]--;
                clothes[i]++;
            } else if (clothes[i + 1] == 2) {
                clothes[i + 1]--;
                clothes[i]++;
            }
        }

        int answer = 0;
        for (int i = 1; i <= n; i++) {
            if (clothes[i] >= 1)
                answer++;
        }

        return answer;
    }
}
```

### 이 배열이 의미하는 것

- `clothes[i]`: **i번 학생이 가진 체육복 개수**
- `clothes[i] == 0`: 체육복이 없어서 빌려야 함
- `clothes[i] == 1`: 자신이 입을 체육복만 있음
- `clothes[i] == 2`: 여벌이 있어서 다른 사람에게 빌려줄 수 있음

처음 모든 학생에게 한 벌씩 있다고 가정해서 `Arrays.fill(clothes, 1)`을 사용한다.

```text
n = 5
인덱스     0  1  2  3  4  5  6
초기값     1  1  1  1  1  1  1
             └ 실제 학생: 1~5 ┘
```

`0`번과 `n + 1`번은 **실제 학생이 아닌 경계용 칸**이다. 가장 앞뒤 학생의 인접 인덱스에 안전하게 접근하기 위해 `n + 2`칸을 만들며, 초기값이 `1`이기 때문에 `== 2` 대여 조건에 걸리지 않는다.

예를 들어 `lost = [2, 3]`, `reserve = [1, 2]`이면:

```text
학생 번호       1  2  3  4  5
초기             1  1  1  1  1
도난 반영        1  0  0  1  1
여벌 반영        2  1  0  1  1
```

2번은 도난도 당하고 여벌도 가져왔기 때문에 최종적으로 1벌이 된다. 따라서 `lost`와 `reserve`의 **공통 원소를 별도로 삭제할 필요가 없다**.

또 학생 번호 순서로 배열을 순회하므로 **정렬도 필요 없다**.

- 시간 복잡도: **O(N)**
- 추가 공간 복잡도: **O(N)**

이 방식에서 가장 중요한 발상은 **번호가 1부터 N까지 이어지는 대상은 번호 자체를 배열의 인덱스로 활용할 수 있다**는 점이다.

## 6. 이번에 배운 Java 문법

### 배열 → ArrayList 변환

`int[]`와 `String[]` 모두 일반 반복문으로 변환할 수 있다. 코딩테스트에서 이 방법을 기본으로 기억해도 충분하다.

```java
int[] arr = {1, 2, 3};
List<Integer> list = new ArrayList<>();
for (int value : arr) {
    list.add(value);  // int -> Integer 오토박싱
}
```

`int[]`에 `Arrays.asList(arr)`를 직접 쓰면 `List<Integer>`가 만들어지지 않으므로 주의한다.

### 배열과 List의 차이

| 기능 | 배열 | List |
|---|---|---|
| 원소 조회 | `arr[i]` | `list.get(i)` |
| 원소 수정 | `arr[i] = x` | `list.set(i, x)` |
| 크기 | `arr.length` | `list.size()` |
| 원소 추가 | 크기 변경 불가 | `list.add(x)` |
| 원소 삭제 | 직접 삭제 불가 | `list.remove(...)` |
| 전체 출력 | `Arrays.toString(arr)` | `System.out.println(list)` |

### `remove()` 오버로딩 주의

```java
List<Integer> list = new ArrayList<>(Arrays.asList(10, 20, 30));

list.remove(1);                    // 인덱스 1 삭제 (20)
list.remove(Integer.valueOf(30));  // 값 30 삭제
```

`String` 리스트에서는 `list.remove("A")`처럼 값을 바로 넣어 삭제할 수 있다.

### for-each로 순회하면서 삭제하지 않기

```java
for (int num : list) {
    // list.remove(Integer.valueOf(num)); // 위험!
}
```

향상된 for문에서 직접 구조를 변경하면 `ConcurrentModificationException`이 발생할 수 있다. 삭제가 필요하면 **일반 인덱스 for문 + 인덱스 보정**, `Iterator.remove()`, `removeIf()` 등을 사용한다.


### 그 밖의 문법

- `Arrays.sort(lost)` : 배열 오름차순 정렬
- `Arrays.fill(clothes, 1)` : 배열의 모든 원소를 `1`로 채움
- `list.contains(num)` : 리스트에 값이 있는지 확인 (ArrayList는 O(N))
- `list.set(i, 999)` : 리스트의 i번째 값을 변경하는 것이며, 삭제하는 것은 아님

## 8. 최종 핵심 정리

- 이 문제는 **앞번호부터 처리하고, 앞사람에게 먼저 빌리는 선택을 확정하는 그리디 문제**이다.
- 처음 풀이는 전략보다 **문제의 예외 조건을 해석한 방식**이 오답의 핵심 원인이었다.
- `lost`와 `reserve`에 동시에 존재하는 학생은 **자기 체육복 1벌만 가진 상태**이므로 대여 대상에서 제외해야 한다.
- 그리디 선택을 왼쪽부터 적용하려면 `lost`가 **정렬되어 있어야 한다**. 입력 정렬은 보장되지 않는다.
- `ArrayList`로 두 집합을 관리해도 되고, **학생 번호를 배열 인덱스로 사용하여 체육복 수를 관리하면 공통 원소 처리와 정렬을 없앨 수 있다.**
- 앞으로는 문제의 제한 조건을 확인한 뒤, **상태를 표현하기 쉬운 자료구조가 무엇인지** 먼저 고민해 보자.
