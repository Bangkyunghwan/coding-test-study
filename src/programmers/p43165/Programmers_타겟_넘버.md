# 프로그래머스 43165 - 타겟 넘버

- 문제 유형: DFS, 완전탐색
- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/43165
- 시간복잡도: O(2^N)
- 공간복잡도: O(N) (재귀 호출 스택)

## 1. 접근 방식 및 사고 흐름

문제를 보자마자 이전에 풀었던 햄버거 다이어트(0/1 Knapsack) 문제의 DFS 풀이가 떠올랐다.
햄버거 다이어트에서는 각 재료를 선택하거나 선택하지 않는 두 가지 경우로 분기했다면, 이번에는 각 숫자를 양수 또는 음수로 계산하는 두 가지 경우로 분기하면 된다고 생각했다.

- 각 숫자에 대해 양수/음수 두 가지로 DFS를 호출한다.
- DFS에 진입하면 전달받은 부호(`sign`)를 이용해 현재 숫자를 누적 합에 반영한다.
- 마지막 숫자까지 계산했을 때 누적 합이 `target`과 같으면 정답 개수를 증가시킨다.

숫자의 개수가 최대 20개이므로 가능한 부호 조합은 최대 2^20개이다. DFS 완전탐색으로 충분히 해결할 수 있다.

처음 생각한 방식으로 한 번에 정답을 맞혔다. 다만 DFS의 인자가 6개나 필요하다는 점이 아쉬웠다.

## 2. AI에게 물어본 모범 답안

```java
class Solution {
    private int[] numbers;
    private int target;

    public int solution(int[] numbers, int target) {
        this.numbers = numbers;
        this.target = target;

        return dfs(0, 0);
    }

    private int dfs(int idx, int sum) {
        if (idx == numbers.length) {
            return sum == target ? 1 : 0;
        }

        return dfs(idx + 1, sum + numbers[idx])
             + dfs(idx + 1, sum - numbers[idx]);
    }
}
```

기존 풀이와 동일한 DFS 완전탐색이지만, 계산 시점과 정답을 구하는 방식이 다르다.

### 2-1. 계산을 수행하는 시점

내 코드는 부호와 기존 합계를 다음 DFS에 전달하고, 호출된 DFS에서 계산한다.

```java
sum += numbers[idx] * sign;
```

모범 답안은 현재 DFS에서 덧셈과 뺄셈을 수행하고, 계산된 결과를 다음 DFS에 전달한다.

```java
dfs(idx + 1, sum + numbers[idx]);
dfs(idx + 1, sum - numbers[idx]);
```

메서드의 인자로 들어가는 식은 메서드가 호출되기 전에 계산된다. 따라서 위 코드는 현재 DFS 호출 스택에서 계산한 결과를 다음 호출에 넘겨주는 것이다.

두 방식의 시간복잡도와 공간복잡도는 동일하다. 다만 미리 계산해서 전달하면 `sign` 인자가 필요 없고, `dfs(0, 0)`으로 탐색을 시작할 수 있다. 종료 조건도 모든 숫자의 처리가 끝난 `idx == numbers.length`로 설정할 수 있다.

`numbers`와 `target`은 인스턴스 변수로 관리하고, `N`은 `numbers.length`로 대체하여 DFS의 인자를 2개로 줄였다.

### 2-2. DFS의 반환값으로 정답 구하기

기존에는 조건을 만족할 때마다 외부의 정답 변수에 `solution++`을 수행했다.

모범 답안에서는 마지막까지 탐색했을 때 조건을 만족하면 1, 아니면 0을 반환한다.

```java
return sum == target ? 1 : 0;
```

그리고 두 하위 DFS가 반환한 정답 개수를 더해서 반환한다.

```java
return dfs(idx + 1, sum + numbers[idx])
     + dfs(idx + 1, sum - numbers[idx]);
```

즉, `dfs(idx, sum)`을 **현재 상태에서 남은 숫자들을 처리하여 타겟 넘버를 만들 수 있는 경우의 수를 반환하는 함수**로 정의한 것이다.

예를 들어 한 DFS의 두 하위 호출이 각각 2와 3을 반환했다면, 해당 DFS는 5를 반환한다. 이런 방식으로 최초 호출까지 결과가 합산되므로 별도의 정답 누적 변수가 필요 없다.

이 방식은 이번에 처음 생각해 본 구현 방식이다. 앞으로 DFS에서 경우의 수를 구할 때는 반환값을 더하는 방법도 고려할 수 있다. 최대/최솟값을 구하는 문제라면 문제에 맞게 `Math.max()` 또는 `Math.min()`으로 하위 호출의 결과를 합칠 수도 있다.

## 3. 다른 풀이 방법

DP로도 해결할 수 있다. 서로 다른 부호 조합이라도 처리한 숫자의 개수와 현재 합이 같다면 이후의 탐색 결과는 동일하기 때문이다. 예를 들어 `[1, 1, 2, 3]`에서 `+1 -1`과 `-1 +1`은 모두 두 숫자를 처리했고 합이 0인 상태이다.

이러한 중복 상태의 결과를 저장하고 재사용하면 O(N × S) 시간에 풀 수 있다(S는 전체 숫자의 합). 다만 이번 문제의 제한사항에서는 DFS만으로 충분하며, 구현도 간단하다.

## 4. 핵심 정리

- 이전에 풀었던 문제의 선택/비선택 구조를 양수/음수 선택 구조로 응용했다.
- 각 원소마다 선택지가 있고 모든 조합을 탐색해야 한다면, 경우의 수가 감당 가능한지 확인한 뒤 DFS 완전탐색을 고려한다.
- 재귀 호출에 계산할 정보를 넘기는 대신 현재 호출에서 계산을 마친 결과를 넘길 수도 있다.
- DFS는 외부 변수를 수정하는 방식뿐 아니라, 각 호출이 담당하는 탐색 범위의 결과를 반환하고 이를 합치는 방식으로도 구현할 수 있다.
