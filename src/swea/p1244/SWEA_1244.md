# SWEA 1244 - 최대 상금

**상태:** 미해결 · 재도전 예정  
**학습일:** 2026-11-10  
**분류:** 완전탐색, DFS, 백트래킹, 중복 상태 가지치기  
**시간 복잡도:** 참고 코드 기준 `O(K × S × N³)` — 아래 복잡도 설명 참고

> 직접 작성한 그리디 코드를 제출했지만 전체 테스트케이스를 통과하지 못했다. 대화를 통해 DFS와 중복 상태 탐색의 개념을 학습했으나, 직접 구현하여 해결한 상태는 아니다. 아래 코드는 학습용으로 제공받은 참고 정답 코드이며, 직접 작성하거나 제출해서 통과한 코드가 아니다. DFS 구현과 Java 메서드를 공부한 뒤 다시 풀어볼 문제로 남긴다.

## 문제에서 해야 하는 일

숫자의 두 자리를 교환하는 작업을 **주어진 횟수만큼 정확히 수행한 뒤**, 만들 수 있는 가장 큰 숫자를 구한다. 최댓값을 먼저 만들었더라도 교환 횟수가 남았다면 나머지 교환도 해야 한다.

## 처음 접근과 시행착오

직접 작성한 시도는 [Solution1.java](Solution1.java)에 있다. [Solution.java](Solution.java)는 아직 구현하지 않은 상태다.

처음에는 왼쪽부터 현재 자리 이후의 최댓값을 찾아 앞으로 가져오는 방식을 생각했다. 첫 번째 자리에서 가장 큰 숫자를 가져온 뒤, 두 번째 자리부터 같은 작업을 반복했다. 교환 횟수를 다 쓰면 중단하고, 끝까지 정렬한 뒤에도 횟수가 남으면 다음처럼 처리하려고 했다.

- 남은 횟수가 짝수면 같은 두 자리를 교환했다가 되돌릴 수 있으므로 숫자를 유지한다.
- 남은 횟수가 홀수면 가장 뒤의 두 자리를 교환한다.
- 같은 숫자가 있다면 같은 숫자끼리 교환해서 값의 변화 없이 횟수를 소모할 수 있으므로, 남은 횟수를 없애는 처리를 추가한다.

남은 횟수의 짝홀과 중복 숫자를 고려한 생각은 유효하다. 하지만 앞부분의 교환 선택과 중복 검사 구현에서 문제가 생겼다.

### 같은 숫자를 발견하자마자 교환 횟수를 쓰는 문제

최댓값을 찾을 때 `>=`를 사용하면 현재 숫자와 같은 숫자도 교환 대상으로 선택될 수 있다.

```text
9912, 교환 1번

앞의 9끼리 교환 → 9912
뒤의 1과 2 교환 → 9921
```

같은 숫자끼리 교환하는 것 자체는 가능하다. 다만 더 크게 만들 수 있는 교환이 남아 있는데 그 기회를 먼저 소모하면 손해다. 같은 숫자끼리의 교환은 필요한 다른 교환을 마치고 남은 횟수를 소모할 때도 활용할 수 있다.

### 가장 오른쪽의 최댓값을 고르는 것도 항상 최선은 아니다

```text
32888, 교환 2번

맨 뒤의 8을 먼저 가져오기:
32888 → 82883 → 88823

뒤에서 두 번째 8을 먼저 가져오기:
32888 → 82838 → 88832
```

앞으로 가져온 숫자는 똑같이 `8`이지만, 뒤로 밀려나는 `3`의 위치가 달라진다. 따라서 같은 최댓값 중 어느 위치를 선택하느냐에 따라 이후 결과가 달라진다. 하나의 교환만 보고 최종 결과까지 확정하기 어려웠다.

코드는 아니다. 예를 들어 `2210`의 앞쪽 `2` 두 개나 `3211`의 마지막 `1` 두 개는 이 검사로 찾지 못한다. 이 수정까지로 전체 풀이가 해결되었다고 기록하지 않는다.

## 다른 접근을 어떻게 떠올리는가?

처음에는 가장 좋아 보이는 교환 하나를 고르려고 했다. 하지만 그 선택을 바로 확정할 근거가 부족했다. 그래서 **가능한 교환 각각을 선택했을 때의 최종 결과를 계산해서 비교하는 방법**을 생각할 수 있다.

이때 먼저 정할 것은 다음 세 가지다.

| 질문 | 이 문제에서의 답 |
|---|---|
| 현재 상황을 표현하려면 무엇이 필요한가? | 현재 숫자와 남은 교환 횟수 |
| 다음으로 할 수 있는 선택은 무엇인가? | 서로 다른 두 자리를 골라 교환하기 |
| 언제 결과를 확인하는가? | 남은 교환 횟수가 0일 때 |

중간 숫자가 현재보다 작아졌다는 이유만으로 탐색을 중단하면 안 된다. 남은 교환으로 더 큰 결과가 나올 수도 있으므로, 정해진 횟수까지 수행한 결과를 비교해야 한다.

## 경우의 수가 너무 많다는 의문과 중복 상태 처리

가장 이해하기 어려웠던 부분은 **6자리에서 두 자리를 고르는 선택을 10번 하면, 모든 경우를 실제로 계산할 수 있는가?**였다. 6자리에서 한 번 교환할 쌍은 `₆C₂ = 15`개다. 중복 처리가 없으면 교환 경로는 `15¹⁰`, 약 5,767억 개까지 생긴다.

중복을 발견하려면 교환을 실제로 해 봐야 한다는 생각도 맞다. 다만 **10번을 모두 교환하고 중복을 확인하는 것이 아니라, 교환할 때마다 현재 상황을 확인한다.** 같은 상황에 도착했다면 그 아래의 탐색 전체를 생략한다.

바꾼 것을 곧바로 되돌리는 경우에만 중복되는 것도 아니다.

```text
123456 → 213456 → 213465
123456 → 123465 → 213465
```

서로 다른 순서로 교환했지만, 두 번 교환한 시점의 숫자는 같다. 둘 다 앞으로 8번 교환해야 한다면 이후 가능한 결과는 똑같다. 앞에서 어떤 교환을 거쳤는지는 이후 탐색에 영향을 주지 않는다.

따라서 기록의 단위는 `(현재 숫자, 남은 교환 횟수)`다. 숫자만 같다고 생략하면 안 된다.

```text
현재 21, 남은 교환 1번 → 12
현재 21, 남은 교환 2번 → 21
```

6개 숫자를 나열하는 서로 다른 배열은 최대 `6! = 720개`다. 남은 횟수가 `0~10`이면 서로 다른 상태는 최대 `720 × 11 = 7,920개`다. 같은 상태를 반복 계산하지 않으면 탐색량을 줄일 수 있다.

## DFS, 백트래킹, 가지치기에서 정리할 점

대화 중 DFS와 백트래킹을 구분하는 설명이 혼란스러웠다. **함수가 돌아오거나 배열을 복구한다는 사실만으로 둘을 구분하지 않는다.** DFS도 깊이 탐색한 뒤 돌아와 다른 갈래를 확인한다.

- **DFS:** 한 선택에서 이어지는 선택을 깊이 먼저 살펴보는 탐색 순서다. 깊이를 나타내는 인자가 반드시 있어야 하는 것은 아니다.
- **백트래킹:** 답의 후보를 선택해 나가며 탐색하고, 선택을 더 이어갈 수 없거나 그 선택의 탐색을 마치면 다른 선택을 시도하는 방법이다. 보통 DFS로 구현한다. 복구용 `swap` 자체가 백트래킹의 정의는 아니다.
- **가지치기:** 더 탐색할 필요가 없는 가지를 중단하는 것이다. 참고 코드의 `visited` 검사는 같은 상태 아래의 탐색을 반복하지 않기 위한 중복 가지치기다.

`visited`가 있어야만 백트래킹인 것도 아니다. 일반 그래프 DFS도 같은 지점을 반복 방문하거나 순환하는 것을 막기 위해 방문 기록을 쓴다.

일반 그래프 DFS의 `graph[node]`는 현재 지점에 연결된 지점들의 배열이다. `for (int next : graph[node])`로 연결된 지점을 하나씩 확인한다. 이 문제는 다음 상태를 만들기 위해 두 자리 `i`, `j`를 선택하므로 반복문이 두 개다. 반복문의 개수나 공통 배열 사용 여부가 DFS를 결정하지는 않는다.

또한 모든 지점을 한 번씩 방문하는 것과 가능한 모든 경로를 시도하는 것은 다르다. 연결된 영역이나 그룹 수를 구하는 일반 그래프 DFS는 방문 기록을 사용하면 `O(V + E)`에 수행할 수 있다. DFS 자체가 항상 지수 시간의 탐색이라는 뜻은 아니다.


## 참고 정답 코드 — 직접 푼 코드가 아님

대화에서 제공받은 Java 8 학습용 코드다. `Solution.java`에 옮겨 구현하거나 제출해서 통과한 상태가 아니다. 나중에 다시 풀 때는 아래 코드를 보지 않고 상태, 다음 선택, 종료 조건부터 정해 본다.

```java
import java.util.Scanner;
import java.util.HashSet;
import java.util.Set;

public class Solution {

    static char[] numbers;
    static String best;
    static Set<String> visited;

    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int T = sc.nextInt();

        for (int tc = 1; tc <= T; tc++) {
            String input = sc.next();
            int changeCount = sc.nextInt();

            numbers = input.toCharArray();
            best = "";
            visited = new HashSet<>();

            dfs(changeCount);

            System.out.println("#" + tc + " " + best);
        }
    }

    static void dfs(int remaining) {
        String current = new String(numbers);
        String key = current + ":" + remaining;

        // 같은 숫자, 같은 남은 횟수를 이미 탐색했다면 중단한다.
        if (visited.contains(key)) {
            return;
        }
        visited.add(key);

        // 정확히 정해진 횟수를 사용한 결과만 비교한다.
        if (remaining == 0) {
            if (current.compareTo(best) > 0) {
                best = current;
            }
            return;
        }

        // 교환할 두 자리를 모두 선택해 본다.
        for (int i = 0; i < numbers.length - 1; i++) {
            for (int j = i + 1; j < numbers.length; j++) {
                swap(i, j);
                dfs(remaining - 1);
                swap(i, j);
            }
        }
    }

    static void swap(int i, int j) {
        char temp = numbers[i];
        numbers[i] = numbers[j];
        numbers[j] = temp;
    }
}
```

## 참고 코드의 실행 흐름

`dfs(remaining)`의 역할은 **현재 `numbers`에서 앞으로 `remaining`번 교환하는 경우들을 탐색하는 것**이다. 인자는 남은 횟수이고, 현재 숫자는 함께 사용하는 배열에 들어 있다.

```java
swap(i, j);
dfs(remaining - 1);
swap(i, j);
```

1. 두 자리를 교환한다.
2. 바뀐 배열에서 남은 교환들을 탐색한다. 호출한 함수는 그 탐색이 끝날 때까지 기다린다.
3. 호출이 끝나면 다음 줄로 돌아와 같은 두 자리를 다시 교환하고 원래 배열로 복구한다.
4. 반복문의 다음 교환을 살펴본다.

`return`은 전체 프로그램을 끝내지 않는다. 현재 호출만 끝내고, 그 함수를 호출했던 곳의 다음 줄로 돌아간다. 중복 상태라서 바로 반환하더라도 호출한 쪽의 복구용 `swap`은 실행된다.

`numbers`는 공유 배열이므로 변경한 내용이 다음 호출에도 보이고, 함수가 돌아온다고 자동 복구되지 않는다. 반면 `dfs(remaining - 1)`은 다음 함수에 계산된 값을 전달한다. 호출한 쪽의 `remaining`을 직접 수정하지 않았으므로, 돌아왔을 때 횟수를 다시 늘릴 필요가 없다. 각 함수 호출의 지역 변수와 반복문 위치도 따로 유지된다.

### `123`을 2번 교환할 때

```text
dfs(2): 123
  첫 교환 0 ↔ 1 → 213
  dfs(1): 213
    교환 0 ↔ 1 → 123
    dfs(0): 123을 정답 후보와 비교하고 반환
    복구 → 213

    교환 0 ↔ 2 → 312
    dfs(0): 312를 정답 후보와 비교하고 반환
    복구 → 213

    교환 1 ↔ 2 → 231
    dfs(0): 231을 정답 후보와 비교하고 반환
    복구 → 213

  dfs(1)이 끝남
  첫 교환을 복구 → 123
  첫 교환의 다음 선택 0 ↔ 2를 진행
```

정확히 두 번 교환해서 가능한 최댓값은 `312`다. 한 번 교환해서 가능한 `321`을 그대로 정답으로 사용할 수 없다.

같은 숫자끼리의 교환도 반복문에서 선택할 수 있다. 반드시 남은 횟수가 0이 될 때까지 탐색하므로, 이 코드에는 남은 횟수의 짝홀을 별도로 처리하는 로직이 필요하지 않다.


## Java 문법과 메서드 복습

문자열·문자·배열의 차이부터, 참고 코드에 쓰인 컬렉션과 메서드까지 다시 확인할 필요가 있다.

| 표현 | 의미 |
|---|---|
| `sc.next()` | 공백 또는 줄바꿈 전까지 문자열 입력. `nextString()`은 없다. |
| `str.length()` | 문자열 길이. 괄호가 있다. |
| `arr.length` | 배열 길이. 괄호가 없다. |
| `list.size()` | `ArrayList` 같은 컬렉션의 원소 수 |
| `str.charAt(i)` | 문자열의 i번째 `char`를 꺼낸다. `str[i]`로 접근하지 않는다. |
| `str.charAt(i) - '0'` | 숫자 문자를 정수로 바꾼다. `'3' - '0'`은 정수 `3`이다. |
| `str.toCharArray()` | 문자열을 문자 배열로 바꾼다. |
| `new String(charArray)` | 문자 배열의 내용을 문자열로 만든다. 이후 배열을 바꿔도 이미 만든 문자열은 바뀌지 않는다. |
| `current.compareTo(best)` | 두 문자열의 사전 순서를 비교한다. 앞이 크면 양수, 같으면 0, 작으면 음수다. |
| `Set<String>` | 문자열을 중복 없이 보관하는 집합 타입 |
| `new HashSet<>()` | 해시를 사용하는 집합을 만든다. 같은 문자열을 여러 번 넣어도 하나만 저장된다. |
| `visited.contains(key)` | 집합에 해당 문자열이 있는지 확인한다. |
| `visited.add(key)` | 집합에 문자열을 넣는다. |
| `visited.clear()` | 집합을 비운다. 참고 코드는 테스트케이스마다 새 집합을 만든다. |
| `StringBuilder.append(value)` | 뒤에 내용을 이어 붙인다. |
| `StringBuilder.toString()` | 쌓은 내용을 `String`으로 만든다. |

`char`는 작은따옴표를 쓰는 기본형이고, `String`은 큰따옴표를 쓰는 참조형이다. `'3'`과 `"3"`은 다른 타입이다. `char`의 산술 연산은 문자 코드값으로 계산되므로 `'3' - '0'`은 가능하지만, `"3" - "0"`은 불가능하다.

참고 코드에서는 문자를 정수로 바꾸지 않고 교환만 한다. 비교할 문자열들은 항상 길이가 같으므로 `compareTo()`의 사전 순서가 숫자 크기 순서와 일치한다. 길이가 다른 일반 숫자 문자열까지 이 방식으로 비교해도 된다는 뜻은 아니다.
