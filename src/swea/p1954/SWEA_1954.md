# SWEA 1954 - 달팽이 숫자

**분류** 구현, 시뮬레이션  
**시간 복잡도** `O(N²)`

## 처음 접근과 막힌 지점

오른쪽으로 갈 때 `x++`, 아래로 갈 때 `y++`를 하면 된다는 건 알고 있었다. 처음에는 이 좌표 변화를 반복문에 직접 써서 오른쪽 끝까지 가고, 이어서 아래쪽 끝까지 가고, 그다음 왼쪽으로 가려고 했다. **현재 방향을 변수에 두고, 막힐 때마다 그 값을 바꿔 가며 이동한다는 발상 자체가 없었다.** 방향이 바뀌는 과정까지 반복문으로 어떻게든 짜 보려다가 막혔다. 가운데부터 거꾸로 채우거나 숫자 사이의 규칙을 찾는 방법도 시도했다.

## 어떻게 생각했어야 했을까?

**한 번 반복할 때마다 현재 방향으로 한 칸 간다**고 생각하니 흐름이 단순해졌다. 현재 방향을 `dir`에 저장해 두면 갈 수 있는 동안은 그 방향으로 계속 가고, 막히는 순간에만 `dir`을 바꿔 새 방향으로 이동하면 된다. 예를 들어 오른쪽 끝에 닿으면 `dir`을 오른쪽에서 아래로 바꾼다. 다음 반복에서도 `dir`은 아래를 가리키므로 계속 아래로 간다.

네 방향에 직접 번호를 붙이면 `dir`이 `0`일 때 `x++`, `1`일 때 `y++`처럼 분기할 수 있다. 오른쪽의 `x++`는 `(x, y)`에 `(1, 0)`을 더하는 동작이고, 아래의 `y++`는 `(0, 1)`을 더하는 동작이다. **방향마다 좌표에 더할 값을 모아 둔 배열**이 `dx`, `dy`다.

```java
// 인덱스 순서: 오른쪽, 아래, 왼쪽, 위
int[] dx = {1, 0, -1, 0};
int[] dy = {0, 1, 0, -1};
```

`dir`을 인덱스로 쓰면 어느 방향이든 `x += dx[dir]`, `y += dy[dir]`로 한 칸 이동할 수 있다. 달팽이가 도는 순서대로 번호를 붙였으니, 방향을 바꿀 때는 `dir = (dir + 1) % 4`로 다음 번호를 고르면 된다.

최종 코드에서는 현재 칸에 숫자를 쓰고 한 칸 이동한다. 배열 밖이거나 이미 채운 칸이면 직전 위치로 돌아와 방향을 바꾼 뒤 다시 이동한다. `new int[N][N]`의 각 칸은 `0`으로 시작하므로 빈 칸인지 바로 확인할 수 있다. 매 테스트 케이스마다 `(0, 0)`에서 오른쪽을 보고 시작한다. 숫자 하나당 하는 일이 일정하고 `N²`개를 채우므로 `O(N²)`이다.

## 구현 중 발견한 실수

숫자를 쓸 때는 `array[y][x]`였는데, 빈 칸을 확인할 때 `array[x][y]`로 읽었다. 3×3에서 `6`을 쓴 뒤 왼쪽의 `(x, y) = (0, 2)`로 가야 한다. 빈 칸인 `array[2][0]` 대신 `3`이 든 `array[0][2]`를 검사해서 너무 일찍 위로 꺾였다. 읽고 쓰는 순서를 `array[y][x]`로 맞춰 해결했다.

## 배운 점

- **상하좌우 이웃을 확인할 때**는 `dr`, `dc`에 방향별 이동량을 정해 두면 같은 검사 코드를 네 번 돌릴 수 있다. 예를 들어 미로의 BFS나 DFS에서는 각 칸에서 `d`를 `0`부터 `3`까지 돌며 `(r + dr[d], c + dc[d])`를 확인한다. 이때 `d`는 지금 검사 중인 이웃의 번호라서 새 칸에서는 다시 `0`부터 시작한다.
- **현재 방향에 따라 다음 행동이 달라질 때**는 그 방향을 `dir`에 저장한다. 달팽이는 지금 가던 방향으로 계속 가고 막힐 때만 `dir`을 바꾼다. 방향별 이동량을 배열에 두는 것과 현재 방향을 다음 반복까지 기억하는 것은 각각 따로 정할 수 있다.
- 다음 격자 문제에서는 행과 열을 `r`, `c`로 두고 `array[r][c]`로 읽고 쓰면 좌표 순서가 덜 헷갈린다.
- 좌표 범위는 `0 <= r, c < N`이고, 채우는 숫자의 범위는 `1`부터 `N²`까지다. 배열의 범위 검사와 숫자를 채우는 반복문의 종료 조건을 따로 확인하자.
