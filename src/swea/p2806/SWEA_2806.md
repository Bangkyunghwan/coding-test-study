# SWEA 2806 — N-Queen

- **문제 유형:** DFS / 백트래킹
- **문제:** N×N 체스판에 퀸 N개를 서로 공격하지 않도록 배치하는 경우의 수 구하기

## 1. 처음 생각한 접근

각 행에 퀸을 하나씩 배치하면, **그 행에서 어느 열에 둘지만 결정**하면 된다.

- `array[r] = c`: `r`행에 배치한 퀸의 열 번호를 저장한다.
- `dfs(r, c, N)`: `(r, c)`에 퀸을 배치하고, **다음 행에서 가능한 열을 탐색**한다.
- 바깥쪽 `for(col)`: 다음 행에 놓을 열 후보를 하나씩 고른다.
- 안쪽 `for(row)`: 앞서 배치한 퀸들과 같은 열이거나 대각선으로 충돌하는지 검사한다.

**전체적인 탐색 방향과 이중 for문의 역할은 처음부터 맞았다.** 문제는 구상한 흐름을 코드로 구현할 때 반복문의 제어 흐름을 잘못 이해한 점이었다.

## 2. 구현하면서 겪은 문제

### (1) 대각선 검사 수식

처음 작성한 조건:

```java
array[row] == Math.abs(col - (r - row))
```

의도는 *"기존 퀸의 열이 현재 열에서 행 차이만큼 떨어져 있으면 충돌한다"*는 것이었다. 발상은 맞지만, 이 식은 양쪽 대각선을 모두 검사하지 못한다. 또한 절댓값을 취해야 하는 대상은 **현재 열과 기존 퀸의 열 사이의 차이**다.

```java
Math.abs(array[row] - col) == r - row
```

예를 들어 기존 퀸이 `(0, 4)`, 새 후보가 `(1, 3)`이라면 열 차이 `|4 - 3| = 1`, 행 차이 `1 - 0 = 1`이므로 대각선에서 충돌한다. 절댓값을 사용하면 왼쪽·오른쪽 대각선을 한 번에 확인할 수 있다.

### (2) DFS 호출 위치와 `break`

**원래는 `dfs()`를 안쪽 `for(row)` 밖, 바깥쪽 `for(col)`의 마지막에 두었다.** 이 위치 자체는 맞았다.

그런데 충돌을 발견하면 `break`로 다음 `col`을 검사하게 될 거라고 생각한 게 문제였다. 실제로 `break`는 **안쪽 `for(row)`만 끝내기 때문에**, 그 아래 `dfs()`까지 실행되어 충돌한 후보도 탐색하게 된다.

오류를 찾는 과정에서 `dfs()`를 안쪽 `for(row)`으로 옮겨 보기도 했지만, 이것도 잘못이었다. **이전 퀸 하나와의 검사만 통과해도 DFS가 호출**되고, 검사에 모두 통과한 경우에는 중복 호출까지 발생할 수 있기 때문이다.

결국 DFS 위치는 **원래대로 바깥쪽 `for(col)` 안, 안쪽 `for(row)` 밖**에 두고, 충돌 여부를 `boolean`으로 판단하도록 수정했다.

```java
for (int col = 0; col < N; col++) {
    boolean possible = true;

    for (int row = 0; row < r; row++) {
        if (array[row] == col ||
            Math.abs(array[row] - col) == r - row) {
            possible = false;
            break;
        }
    }

    if (possible) dfs(r, col, N);
}
```

핵심은 **한 열에 대한 이전 퀸 검사가 끝난 뒤**, 그 열이 유효할 때만 다음 DFS를 호출하는 것이다.

## 3. AI에게 물어본 모범 답안과 비교

내 코드로 정답을 구한 뒤, AI가 제안한 **다른 DFS 구성 방식**을 비교했다. 내 정답 코드는 소스 파일에 있으므로 여기서는 **비교 대상인 AI 모범 코드 전체**를 남긴다.

### AI에게 물어본 모범 답안

```java
import java.util.*;

public class Solution {
    static int N;
    static int count;
    static int[] queens;

    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int T = sc.nextInt();

        for (int tc = 1; tc <= T; tc++) {
            N = sc.nextInt();
            count = 0;
            queens = new int[N];

            dfs(0);

            System.out.println("#" + tc + " " + count);
        }
    }

    // row행에 퀸을 놓을 수 있는 모든 경우 탐색
    static void dfs(int row) {
        if (row == N) {
            count++;
            return;
        }

        for (int col = 0; col < N; col++) {
            if (isValid(row, col)) {
                queens[row] = col;
                dfs(row + 1);
            }
        }
    }

    // (row, col)에 퀸을 놓을 수 있는지 확인
    static boolean isValid(int row, int col) {
        for (int prev = 0; prev < row; prev++) {
            if (queens[prev] == col)
                return false;

            if (Math.abs(queens[prev] - col) == row - prev)
                return false;
        }
        return true;
    }
}
```

### 내 코드와 무엇이 달랐나?

**내 방식:** `dfs(r, c, N)`는 **이미 정해진 `(r, c)`에 퀸을 놓고, 다음 행에 놓을 수 있는 열을 검사**한다. 그래서 `main`에서 첫 행의 열을 하나씩 선택해 `dfs(0, i, N)`으로 시작했다.

```java
// 내 코드의 흐름 (핵심 부분만)
array[r] = c;   // 이번 DFS에서 전달받은 위치에 배치
r++;

// 다음 행의 모든 col을 검사한 다음...
if (possible) dfs(r, col, N);
```

**AI 방식:** `dfs(row)`는 **전달받은 행에서 가능한 열을 직접 검사하고, 배치까지 한 뒤 다음 행으로 넘어간다.** 따라서 `main`에서는 `dfs(0)`만 호출하면 된다.

```java
// AI 코드의 흐름 (핵심 부분만)
for (int col = 0; col < N; col++) {
    if (isValid(row, col)) {
        queens[row] = col;  // 이번 행의 위치를 이 DFS에서 결정
        dfs(row + 1);
    }
}
```

| 비교 | 내 코드 | AI 모범 코드 |
|---|---|---|
| DFS 함수의 의미 | 지정된 `(r, c)`에 놓은 후 **다음 행** 검사 | `row`행의 후보를 검사하고 **그 행에** 놓기 |
| 함수 인자 | `dfs(r, c, N)` | `dfs(row)` |
| 첫 탐색 시작 | `main`에서 열별로 `dfs(0, i, N)` | `main`에서 `dfs(0)` 한 번 |
| 종료 조건 | `r == N - 1` (마지막 행의 후보는 호출 전에 검증) | `row == N` (모든 행의 배치 완료) |
| 충돌 검사 | DFS 내부에서 `boolean possible` 사용 | 별도 `isValid()`에서 `true/false` 반환 |

**유효성 검사 알고리즘 자체는 똑같다.** 두 코드 모두 이전 퀸과 같은 열인지, 행 차이와 열 차이의 절댓값이 같은지 확인한다. AI 코드는 그 검사를 별도 함수로 빼서 DFS 본문의 흐름이 더 단순하게 보인다.

**이번 비교에서 배운 점:** DFS는 반드시 한 가지 형태로 작성하는 것이 아니다. **`dfs(인자)`에 어떤 작업을 맡길지 먼저 정하면** 필요한 인자, 퀸을 기록하는 시점, 재귀 호출과 종료 조건이 자연스럽게 결정된다. 다음에는 `dfs(row)`처럼 **현재 행에서 후보 선택 → 유효성 확인 → 배치 → 다음 행 호출**을 한 함수에 묶는 구조도 떠올려 볼 수 있다.

## 4. 이번 문제에서 배운 점

- **`break`의 범위:** 중첩 반복문에서 `break`는 가장 안쪽 반복문만 종료한다. 내가 생각한 "현재 열을 포기하고 다음 열로 이동"과 실제 실행 흐름이 달랐다.
- **DFS 호출 시점:** 이전 행들을 **모두 검사한 다음**에 호출해야 한다. 안쪽 반복문에서 한 번 검사를 통과한 것과 전체 검사가 끝난 것은 다르다.
- **대각선 검사:** 두 퀸의 **열 차이의 절댓값과 행 차이**가 같으면 대각선에서 충돌한다.
- **DFS 함수 역할:** 내 `dfs(r, c)`와 AI의 `dfs(row)`는 담당하는 일이 달랐다. **완성된 모범 코드를 비교하면서** 현재 행의 후보 선택까지 DFS에 맡기면 코드 흐름이 단순해진다는 점을 배웠다.

## 5. 다음에 비슷한 문제를 풀 때 확인할 것

1. **상태를 어떻게 표현할까?** 예: 각 행의 퀸 위치를 `array[row] = col`로 저장.
2. **DFS 함수는 정확히 무슨 일을 할까?** 이미 결정된 위치를 처리할지, 현재 위치의 후보부터 고를지 먼저 정하기.
3. **재귀 호출 전에 검사해야 하는 조건은 무엇일까?** 하나의 후보에 대해 필요한 검사를 모두 끝냈는지 확인.
4. **`break`·`continue` 이후 어디로 실행이 이동할까?** 특히 중첩 for문에서는 실제 흐름을 따라가 보기.

## 최종 핵심 정리

> 이번 문제는 DFS 접근과 이중 for문 설계 자체보다 **생각한 실행 흐름과 실제 코드 실행 흐름이 달랐던 점**이 어려웠다. 특히 `break`는 안쪽 반복문만 종료한다는 사실과, **모든 유효성 검사를 마친 뒤에 DFS를 호출해야 한다**는 점을 기억하자.
