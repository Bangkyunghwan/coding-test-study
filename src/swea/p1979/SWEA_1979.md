# SWEA 1979 — 어디에 단어가 들어갈 수 있을까

**알고리즘:** 구현, 완전탐색  
**시간 복잡도:** O(N² × K)  
**핵심:** 모든 칸을 시작 위치로 검사하되, **정확히 K칸의 공간인지** 확인하기 위해 앞뒤 조건까지 검사한다.

## 1. 처음 접근 방식

모든 칸을 순회하면서, 각 칸을 단어의 시작 위치라고 가정하고 조건을 검사하려고 했다.

- 현재 칸부터 **오른쪽으로 K칸**, **아래쪽으로 K칸**을 각각 확인한다. (현재 칸을 포함하므로 추가로 이동하는 칸은 K-1칸이다.)
- 검사하는 K칸이 모두 `1`이어야 한다.
- 검사 도중 배열 범위를 벗어나면 안 된다.
- 조건을 만족하면 정답을 증가시킨다.

별도의 특별한 알고리즘을 떠올리기보다는 **모든 칸을 확인하고, 문제에서 요구하는 조건을 직접 구현하는 방식**으로 접근했다.

전체적인 접근 방향은 맞았지만, 구현하면서 빠뜨린 조건들을 하나씩 발견했다.

## 2. 구현하면서 발견한 문제와 수정 과정

### ① K칸이 모두 1이어도 정답이 아닐 수 있다

처음에는 시작점부터 K칸이 모두 `1`이고 범위를 벗어나지 않으면 된다고 생각했다.

그런데 K칸을 검사한 **바로 다음 칸도 `1`이면**, 실제로는 길이가 K보다 긴 공간이다.

예를 들어 K=3일 때:

```text
0 1 1 1 1 0
  └───┘
  3칸을 검사하면 모두 1이지만, 실제 공간은 4칸이다.
```

→ K칸 바로 다음 칸이 배열 안에 있고 `1`이라면 정답으로 인정하지 않는 조건을 추가했다.

### ② 배열 크기 N과 인덱스의 경계에서 실수했다

다음 칸을 검사하는 조건을 작성하면서 `N`과 인덱스를 비교할 때 등호를 포함해야 하는지 헷갈렸다. 그 과정에서 배열 범위를 벗어나는 오류가 발생했다.

예를 들어 `N=5`, 시작 인덱스 `c=2`, `K=3`이면:

- 실제 검사할 칸: 인덱스 `2, 3, 4`
- 마지막 검사 칸: `c + K - 1 = 4`
- 그 다음 칸: `c + K = 5`
- 배열의 유효한 인덱스: `0 ~ 4`

따라서 K칸이 배열 안에 들어가는 조건은 `c + K <= N`이고, **K칸 다음 위치를 실제로 조회할 수 있는 조건**은 `c + K < N`이다.

```java
if (c + k < n && array[r][c + k] == 1) {
    return false;
}
```

→ 배열의 크기와 마지막 인덱스는 다르다는 점을 기억해야 한다. 헷갈릴 때는 실제 숫자를 넣어서 마지막 칸과 그 다음 칸의 인덱스를 계산해 본다.

### ③ 가로 검사 실패가 세로 검사까지 막았다

처음에는 하나의 `check` 메서드 안에서 오른쪽과 아래쪽을 모두 검사했다.

그런데 오른쪽 검사가 실패했을 때 `return false`로 메서드를 끝내 버리니, **아래쪽은 검사조차 하지 못하는 문제**가 있었다.

오른쪽에 단어가 들어가지 않는다고 해서 아래쪽에도 들어가지 않는 것은 아니다.

→ `checkRightDirection()`과 `checkBottomDirection()`을 별도의 메서드로 분리했다.

### ④ 시작 위치 바로 앞의 공간도 검사해야 한다

다시 문제를 확인하면서 **모든 칸이 단어의 시작 위치가 될 수 있는 것은 아니라는 점**을 발견했다.

예를 들어 K=3일 때:

```text
인덱스: 0 1 2 3 4 5
값:     0 1 1 1 1 0
             ↑
           시작(c=2)
```

이 위치에서 시작하면 `2, 3, 4`번 칸이 모두 `1`이고, 그 다음 칸은 `0`이다. 하지만 시작 위치 바로 왼쪽인 `1`번 칸도 `1`이므로 실제로는 길이가 4인 공간이다.

더 중요한 것은, 어떤 위치부터 K칸이 모두 `1`이어도 **그 시작 위치 바로 앞이 `1`이면** 실제 공간의 시작이 아니라는 점이다.

→ 가로 검사는 시작 위치의 왼쪽 칸, 세로 검사는 시작 위치의 위쪽 칸이 `1`인지 추가로 확인했다.

```java
// 가로: 시작 위치 바로 왼쪽
if (c - 1 >= 0 && array[r][c - 1] == 1) return false;

// 세로: 시작 위치 바로 위쪽
if (r - 1 >= 0 && array[r - 1][c] == 1) return false;
```

배열의 맨 왼쪽이나 맨 위라서 이전 칸이 없다면, 그 자체로는 문제가 되지 않는다.

### ⑤ 같은 위치에서 가로와 세로가 모두 가능하면 2개로 센다

처음에는 오른쪽 검사와 아래쪽 검사를 `||`로 연결해서, 둘 중 하나라도 성공하면 정답을 한 번 증가시키려고 했다.

하지만 이 문제는 **단어가 들어갈 수 있는 위치를 방향별로 세는 문제**다.

같은 칸을 공유하더라도 가로로 길이 K인 공간이 하나 있고 세로로 길이 K인 공간도 하나 있으면, 총 **2개**다.

→ 가로와 세로를 각각 검사해서, 성공한 방향마다 정답을 증가시키도록 수정했다.

```java
if (checkRightDirection(i, j, N, K))
    solution++;

if (checkBottomDirection(i, j, N, K))
    solution++;
```

## 3. 최종적으로 검사해야 하는 조건

어떤 칸을 단어의 시작점으로 볼 때, 한 방향에 대해 다음 조건을 모두 만족해야 한다.

1. **시작점 바로 이전 칸이 `1`이면 안 된다.** (배열 밖이라면 상관없다.)
2. **시작점부터 K칸이 모두 `1`이어야 한다.**
3. **그 K칸이 배열 범위를 벗어나면 안 된다.**
4. **K칸 바로 다음 칸이 `1`이면 안 된다.** (배열 밖이라면 상관없다.)

이렇게 확인해야 단순히 `1`이 K개 연속된 구간이 아니라, **길이가 정확히 K인 공간**을 셀 수 있다.

가로와 세로는 서로 독립적으로 검사한다.

## 4. 이번 문제에서 배운 점

**① 구현 문제는 조건을 빠짐없이 파악하는 것이 중요하다.**

처음에 생각한 탐색 방법은 맞았지만, K칸만 검사해서는 정확히 K칸의 공간인지 알 수 없었다. 검사 구간의 앞과 뒤까지 확인해야 한다.

**② 배열 경계 조건은 실제 인덱스를 대입해 확인한다.**

배열 크기는 `N`이지만 마지막 인덱스는 `N-1`이다. 특히 `c+K-1`(마지막 검사 칸)과 `c+K`(그 다음 칸)을 구분해야 한다.

**③ 독립적인 검사는 한쪽의 실패로 다른 쪽이 중단되면 안 된다.**

가로 검사가 실패해도 세로 검사는 성공할 수 있다. `return`이 어느 범위의 검사를 종료하는지 신경 써야 한다.

**④ 무엇을 정답 1개로 세는지 정확히 이해해야 한다.**

같은 위치에서도 가로와 세로가 각각 가능하면 2개다. `||`로 한 번만 증가시키는 것과 각 방향에서 따로 증가시키는 것은 다르다.

**⑤ 완전탐색과 구현은 함께 쓰일 수 있다.**

이번 풀이는 모든 칸을 후보로 확인한다는 점에서 **완전탐색**, 후보마다 문제의 조건을 직접 검사한다는 점에서 **구현**이다. DFS나 DP 같은 별도의 알고리즘은 필요하지 않았다.

## 5. 앞으로 구현 문제를 풀 때 생각할 순서

1. 정답이 되는 **정확한 조건**을 먼저 정리한다.
2. 가장 직관적인 방법으로 모든 후보를 검사할 수 있는지 생각한다.
3. 검사할 구간뿐 아니라 **바로 앞과 뒤의 조건**도 필요한지 확인한다.
4. 배열의 첫 칸, 마지막 칸 등 **경계 사례**를 직접 대입해 본다.
5. 여러 검사가 서로 독립적인지, **동시에 성공했을 때 몇 개로 세는지** 확인한다.
6. 구현 후 입력 크기와 시간 복잡도를 확인한다.

## 6. 최종 핵심 정리

이번 문제는 특별한 알고리즘을 몰라서 오래 걸린 것이 아니라, **정답으로 인정되는 조건을 구현하면서 하나씩 발견했기 때문에** 시간이 걸렸다.

모든 칸에서 가로와 세로를 검사하겠다는 처음의 접근은 맞았다. 중요한 것은 **K칸이 모두 1인지** 확인하는 것에서 끝내지 않고, **정확히 K칸만 들어갈 수 있는 공간인지** 앞뒤까지 검사하는 것이었다.

앞으로 기억할 질문:

> 내가 지금 확인한 조건만으로 정말 정답이라고 판단할 수 있을까? 빠진 예외 조건은 없을까?

> 배열의 경계에서 조건이 달라지지는 않을까?

> 서로 독립적인 검사라면 하나가 실패하더라도 나머지를 끝까지 확인하고 있는가?
